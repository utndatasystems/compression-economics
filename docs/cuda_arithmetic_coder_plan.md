# CUDA arithmetic coder implementation plan

## Goal and baseline

Target the repository's **MSAC v2 target-interval** archive first. Its reference encoder is `src/coding/multistream_ac.py` with `target_interval=True`; `src/coding/parallel_ac.py` is the compiled CPU interval encoder; `src/coding/device_ac.py` is the current PyTorch decoder on the model device. The latter avoids a vocabulary-sized host transfer but launches many small tensor operations and synchronizes on each renormalization loop. A custom CUDA implementation should keep coder state and next token IDs beside the model while producing **exactly the same archive bytes and decoded symbols** as the reference.

This is a correctness and performance experiment, not a new wire format. Keep MSAC v2 header, stream directory, bit counts, big-endian bit order, zero padding, and CRC32. `MultistreamACDecoder` should remain the host validator/fallback. The outer GMMS archive holds seeds and model metadata; model weights remain an external dependency.

## Arithmetic contract

Read `src/coding/encoding.py`, `src/coding/parallel_ac.py`, `src/coding/target_interval.py`, and the paired archive helper before coding. For the default state, `state_bits = 32`, `mask = 2^32 - 1`, and the nominal frequency budget is `T = 262144`. Given a float32 probability row of `A` entries, convert to float64, normalize by its float64 row sum, and compute `f[i] = 1 + floor((p[i] / sum(p)) * (T - A))`. Prefix-sum `f` into CDF `C` with `C[0] = 0`. **The actual total is `C[A]`, which may vary per row**; do not substitute the nominal budget. CPU and CUDA reductions can differ near a floor boundary, so byte-exact compatibility must be tested on representative model outputs. An initial kernel can take the exact integer CDF or selected `(C[token], C[token+1], C[A])` produced by the existing Torch code and tackle fused quantization only after this works.

For each symbol, use 64-bit intermediates and the old `low` for both updates:

```text
range = high - low + 1
new_low  = low + floor(C[token]   * range / total)
new_high = low + floor(C[token+1] * range / total) - 1
```

The decoder first computes `value = floor(((code - low + 1) * total - 1) / range)` and chooses the largest `token` for which `C[token] <= value` (equivalent to upper_bound(C, value) - 1). Apply the same interval update. Reproduce the reference's shift-before-underflow renormalization order, initial `state_bits` code bits, zero bits after the declared bit count, MSB-first packing, terminal `1` bit, and zero padding. Guard `(1 << state_bits) * nominal_total <= INT64_MAX`; wider settings need a separate arithmetic implementation. Keep exact symbol counts per stream and reject out-of-range tokens, malformed intervals, or exhausted streams.

## Staged implementation

1. **Encode supplied intervals (implemented in `src/coding/cuda_ac.py`).** Accept contiguous int64 arrays shaped `[steps, streams]` for lower, upper, and actual total, plus each stream's symbol count. Give one thread (or one lane) ownership of each stream's sequential coder state. Emit to a bounded, private byte workspace per stream with a separate bit count and overflow flag. Start with ample caller-allocated capacity and a checked retry path; do not silently truncate. A CPU packer can initially build the MSAC header, per-stream CRC32, and payload directory. Compare the complete archive byte-for-byte with both Python and Numba reference encoders for the same intervals.
2. **Decode supplied CDFs.** Parse and validate MSAC framing on the host, then upload packed payloads and bit counts. Keep per-stream `low`, `high`, `code`, bit cursor, decoded count, and active mask in GPU buffers. Given int64 CDF rows shaped `[streams, alphabet + 1]`, use an inverse CDF search and write int64 or int32 token indices to a GPU tensor. One thread per stream is the simple baseline; test a warp-per-stream search only if alphabet size makes it useful. The kernel should expose an error flag for invalid state; check it at a controlled boundary. Compare all tokens and completion counts with `DeviceMultistreamACDecoder` and the host decoder.
3. **Connect model output.** Accept the masked model probabilities in the same order as `TokenPredictor.tokens_list`; compute/lookup the integer CDF on the device and return token IDs on the device. Change prompt assembly in `src/global_mask_compressor.py` and `src/prediction.py` so token IDs do not take a `.cpu().tolist()` trip each decode step. Use a fixed-shape prompt/KV-cache path where practical; otherwise the remaining host prompt work can dominate. Keep an opt-in backend and preserve host fallback.
4. **Fuse only after profiling.** Candidate fusion points are quantization plus prefix scan and inverse search, or the target-interval encoder plus packing. A large alphabet needs a parallel reduction/scan; a single thread scanning all probabilities is unlikely to be useful. The arithmetic state itself remains sequential *within* a stream, so increase the number of independent streams or process longer chunks per launch. Warp divergence from different renormalization counts is expected. Evaluate whether batched kernels, CUDA Graph replay, or persistent inference-worker state lower launch overhead before building a persistent kernel.

A PyTorch C++/CUDA extension registered as custom operators is a practical interface. Use the caller's current CUDA stream, support contiguous tensors first, validate device/dtype/shape, and avoid hidden device synchronizations or implicit host copies. Keep allocations outside the per-token hot path. Compile against the server's installed PyTorch/CUDA stack; pin and record those versions. A JIT-built extension is acceptable for the experiment, but build/compile time must be excluded from decode measurements.

## Tests and measurement gates

- Unit traces: all-zero/near-zero probabilities, alphabet size 2 and near the allowed maximum, short and zero-symbol streams, uneven stream lengths, renormalization and underflow cases, payload byte boundaries, and malformed bit counts/CRC. For valid traces, assert full archive byte equality, exact token recovery, and zero padding. Use deterministic seeds.
- CPU/CUDA quantization: compare *integer* frequencies, CDFs, selected intervals, and totals on saved model probability rows. A token recovery test alone can miss a count mismatch that surfaces later. If GPU reductions produce different counts, use a deterministic compatible reduction or explicitly limit the experiment to matched GPU encode/decode archives; document any wire compatibility limit.
- End-to-end: exact decoded token IDs and UTF-8 text on a matched Qwen/text8 archive. Benchmark both `--ac-decode-backend host` and the new backend with the same model revision, dtype, batch size, mask, and archive. A CPU-created archive is a separate cross-device compatibility check.
- Timing: report compression and decompression separately, symbols/s, total wall time, coder time, inference time, kernel time with CUDA events, host/device transfer bytes, peak GPU memory, archive bytes/token including framing, and p50 plus spread across warmed repetitions. Synchronize at measurement boundaries. Record GPU model, driver, CUDA runtime/toolkit, PyTorch, model revision, commit, input hash, and archive hash. Compare against the host, Numba, and PyTorch device baselines. No speedup claim until the live model path shows one.
- Profile: locate stalls and copies with [Nsight Systems](https://docs.nvidia.com/nsight-systems/UserGuide/) and inspect occupancy, memory traffic, and divergent instructions with [Nsight Compute](https://docs.nvidia.com/nsight-compute/ProfilingGuide/). Report traces alongside benchmark JSON under ignored `artifacts/papers/coding-survey/`.
